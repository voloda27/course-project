## 2. Призначення програми

Програма допомагає одній людині вести облік власних грошей: бачити, скільки коштів є на кожному рахунку (готівка, картка, скарбничка), записувати доходи й витрати за категоріями та знаходити потрібні операції. Баланс рахунку змінюється автоматично під час проведення, редагування й видалення операцій, тому користувачеві не потрібно перераховувати його вручну.

Усі суми, рахунки й операції — вигадані навчальні дані. Реальні банківські дані, номери карток і платежі в програмі не використовуються.

## 3. Користувачі

Користувач один — власник бюджету (наприклад, студент, який отримує стипендію та має підробіток). Реєстрація, вхід і ролі не передбачені.

## 4. Задача, яку розв'язує програма

Без програми облік ведуть у зошиті або в голові: важко зрозуміти, скільки грошей залишилося на кожному рахунку, на що вони витрачаються, і легко записати витрату, якої фактично не могло бути (більшу, ніж є грошей). Програма:

- зберігає рахунки, категорії та операції в одному місці;
- проводить операцію доходу чи витрати й одразу змінює баланс рахунку;
- **не дозволяє провести витрату, якщо на рахунку недостатньо коштів**;
- дає змогу швидко знайти, відфільтрувати й відсортувати операції.

**Основна операція предметної області** — проведення витрати з рахунку з перевіркою достатності коштів. Аналог видачі книги в бібліотеці: там перевіряють наявність примірника, тут — наявність грошей на рахунку.

## 5. Дані

Дані зберігаються у файлі `db.json`, який обслуговує JSON Server. Ідентифікатори — рядки (`"1"`, `"2"` …); для нових записів id створює JSON Server. Грошові суми — числа з не більше ніж двома знаками після коми, валюта одна — гривня (₴).

### 5.1 Колекція `accounts` — рахунки

| Поле | Тип | Обмеження |
| --- | --- | --- |
| id | string | Унікальний, створює JSON Server |
| name | string | Обов'язкове, 2–40 символів після обрізання пробілів; унікальне серед рахунків без урахування регістру |
| type | string | Одне зі значень: `cash` (готівка), `card` (картка), `savings` (заощадження) |
| balance | number | ≥ 0 і ≤ 10 000 000; не більше 2 знаків після коми. Під час створення — початковий залишок; надалі змінюється лише через операції |

### 5.2 Колекція `categories` — категорії операцій

| Поле | Тип | Обмеження |
| --- | --- | --- |
| id | string | Унікальний, створює JSON Server |
| name | string | Обов'язкове, 2–30 символів; унікальне в межах свого типу без урахування регістру |
| type | string | `income` (дохід) або `expense` (витрата); не можна змінити, якщо за категорією вже є операції |

### 5.3 Колекція `transactions` — грошові операції

| Поле | Тип | Обмеження |
| --- | --- | --- |
| id | string | Унікальний, створює JSON Server |
| type | string | `income` (дохід) або `expense` (витрата) |
| amount | number | > 0 і ≤ 1 000 000; не більше 2 знаків після коми |
| date | string | Формат `РРРР-ММ-ДД`; реальна дата не раніше 2000-01-01 і не пізніше сьогоднішньої |
| accountId | string | id наявного рахунку |
| categoryId | string | id наявної категорії; тип категорії має збігатися з типом операції |
| comment | string | Необов'язковий, до 100 символів |

### 5.4 Зв'язки

- Рахунок 1 — N операцій (`transactions.accountId → accounts.id`).
- Категорія 1 — N операцій (`transactions.categoryId → categories.id`).

**Важливо.** JSON Server 0.17.4 розпізнає поля з закінченням `Id` як зовнішні ключі: під час `DELETE /accounts/1` він мовчки видаляє й усі операції з `accountId: "1"` (перевірено на навчальних даних). Тому програма перед видаленням рахунку чи категорії сама перевіряє, чи немає пов'язаних операцій, і лише тоді надсилає запит `DELETE`. Інакше разом із рахунком зникла б історія операцій.

Нові записи, створені через `POST`, отримують від JSON Server рядковий id випадкового вигляду (наприклад, `"OOPhuo1"`); навчальні записи мають id `"1"`, `"2"` ….

| ФВ-13 | Пошук операцій за текстом у коментарі або назві категорії | Показано лише операції, що містять введений текст (без урахування регістру) |
| ФВ-14 | Фільтрування операцій за типом, рахунком, категорією та періодом (дата від — до) | Фільтри працюють разом; скидання фільтрів повертає повний список |
| ФВ-15 | Сортування операцій за датою або сумою (за зростанням / спаданням) | Порядок рядків змінюється відповідно до вибору |
| ФВ-16 | Перевірка введення в усіх формах | Некоректні дані не надсилаються на сервер; біля форми показано зрозуміле повідомлення |
| ФВ-17 | Повідомлення про недоступність сервера | Якщо JSON Server зупинено, користувач бачить повідомлення «Перевірте, чи запущений JSON Server» |

## 7. Головне правило перевірки даних

> **Витрату можна провести лише тоді, коли її сума не перевищує поточний баланс рахунку: `amount ≤ account.balance`.**

Якщо умова не виконується, операція не зберігається, баланс не змінюється, а користувач бачить повідомлення, наприклад: «Недостатньо коштів на рахунку "Готівка": доступно 1 267,60 ₴, потрібно 1 500,00 ₴».

Із цього правила випливає загальна вимога: **баланс будь-якого рахунку ніколи не стає від'ємним** — ні після проведення, ні після редагування, ні після видалення операції (наприклад, не можна видалити дохід, якщо ці гроші вже витрачено).

## 9. Межі проєкту

**Входить:**

- облік рахунків, категорій та операцій (додавання, перегляд, редагування, видалення);
- проведення доходів і витрат з автоматичною зміною балансу та перевіркою достатності коштів;
- пошук, фільтрування й сортування операцій;
- перевірка введення та оброблення недоступності сервера.

**Не входить:**

- реєстрація, вхід, ролі та кілька користувачів;
- реальні банківські рахунки, картки, платежі, імпорт банківських виписок;
- кілька валют і курси обміну;
- переказ між власними рахунками;
- місячні бюджети (ліміти) категорій, звіт за період і підсумкові показники, експорт, історія змін — це можливості рівня IV;
- мобільний застосунок і розгортання в інтернеті.

## 10. Для чого потрібні Live Server і JSON Server

- **JSON Server** (версія 0.17.4) — навчальний REST-сервер, який без написання власного бекенду перетворює `db.json` на HTTP API на адресі `http://localhost:5000`. Він відповідає на запити `GET /accounts`, `GET /accounts/1`, `POST`, `PATCH`, `DELETE` і записує зміни у `db.json`, тому дані зберігаються між запусками.
- **Live Server** (розширення VS Code) — локальний вебсервер, який відкриває `index.html` у браузері через `http://127.0.0.1:5500`. Сторінку потрібно відкривати саме через сервер, а не подвійним кліком по файлу, щоб браузер дозволив запити `fetch` до JSON Server. Live Server також оновлює сторінку після збереження `index.html` чи `app.js` (зміни `db.json` у налаштуваннях виключено, щоб сторінка не перезавантажувалася після кожної операції).

Ці два сервери працюють незалежно: JSON Server надає дані, Live Server показує сторінку, а `app.js` пов'язує їх HTTP-запитами.
